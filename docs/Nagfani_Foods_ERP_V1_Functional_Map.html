2. The 8 Operational Workflows (End-to-End Working of V1)

This section details the precise operational workflows that run the day-to-day operations of Nagfani Foods, from customer order intake to physical van delivery and accounting ledger synchronization.

WF-01 Customer Order Booking & Real-Time Stock Reservation POST /orders

Actor: Order Executive (or Admin) • Interface: /orders/new • Frequency: High-volume morning booking window.

sequenceDiagram autonumber actor Staff as Order Desk Staff participant UI as NewOrder.jsx participant API as orderRoutes.js participant STK as stockService.js participant DB as MongoDB (ACID Session) participant WS as Socket.IO Bus Staff->>UI: Select Customer (Party) UI->>API: GET /parties/:id (Fetch Outstanding & Credit Limit) Staff->>UI: Add Items (e.g. Urad Hari Mirch Papad) UI->>API: GET /parties/:id/rates?itemId=... API-->>UI: Return Last Agreed Rate (or MRP fallback) Staff->>UI: Enter Quantity & Confirm Order UI->>API: POST /api/v1/orders API->>STK: checkStockAvailability(items, godownId) alt Available Stock is Insufficient STK-->>UI: Return Stock Warning (Admin override allowed) end API->>DB: Start Transaction API->>DB: Generate Sequential 'ORD-XXXXXX' API->>DB: If B2C, Generate Challan 'DC-XXXXXX' API->>STK: reserveOrderStock(order, session) STK->>DB: Write 'reserve' movement (Physical: 0, Reserved: +qty) STK->>DB: Update StockLevel (Available = Physical - Reserved) API->>DB: Enqueue sync_outbox record API->>DB: Commit Transaction API->>WS: emitEvent('order:created', order) WS-->>UI: Update Order Board & Dashboard KPI
1
Party Selection & Credit Intelligence: Selecting a customer immediately triggers a live query showing outstanding debt and credit limit. If overdue exceeds credit terms, visual warnings highlight risk.
2
Rate-Memory Auto-Suggest: Each item line automatically fetches the specific customer's historical rate via RateHistory. Staff can override, but the historical rate saves clerical time.
3
Reservation Boundary: Stock is reserved instantly. Physical stock stays unchanged in the godown, but available stock drops, preventing double-selling.

WF-05 Recipe BOM Creation & Food Manufacturing Batch Execution POST /production

Actor: Production Lead • Interface: /manufacturing/new & /boms • Focus: Ingredient conversion & variance control.

sequenceDiagram autonumber actor Chef as Production Supervisor participant UI as NewProduction.jsx participant API as manufacturingRoutes.js participant STK as stockService.js participant DB as MongoDB Session Chef->>UI: Select Product (e.g. 'Urad Hari Mirch Papad 500g') UI->>API: GET /boms/for-product/:id API-->>UI: Return Active BOM (Base: 100 kg Recipe) Chef->>UI: Enter Actual Batch Yield: 250 kg UI->>UI: Auto-scale theoretical ingredients (2.5x) Chef->>UI: Enter Actual Ingredient Consumption & Wastage Chef->>UI: Click 'Confirm & Post Batch' UI->>API: POST /api/v1/production API->>DB: Start Transaction API->>DB: Generate 'PRD-XXXXXX' & Lot Number loop For each raw ingredient API->>STK: recordStockMovement(consumption, -actualQty) STK->>DB: Deduct Raw Material Physical Stock end API->>STK: recordStockMovement(production_in, +producedQty) STK->>DB: Inward Finished Goods Physical Stock alt Wastage is greater than 0 API->>STK: recordStockMovement(wastage, -wastageQty) end API->>DB: Log BOM vs Actual Variance API->>DB: Enqueue Tally Stock Journal in sync_outbox API->>DB: Commit Transaction

Mathematical Variance Formula: Variance = ActualQty - (BOM_BaseQty * (ProducedQty / BOM_Yield)). Any positive variance represents excess usage; negative variance indicates recipe savings.
